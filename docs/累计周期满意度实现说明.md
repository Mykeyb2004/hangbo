# 累计周期满意度实现说明

累计批次（例如 `1-9月`、`1-12月`、`Q1`）通过现有单周期统计引擎分别计算每个独立周期，跨期聚合下级指标并保留两位后，按“有效下级指标 → 一级指标 → 客群总分 → 整体满意度”逐层等权求均值。单周期批次（例如 `1-2月`、`3月`）仍执行原有 `run_directory_batch` 路径。

2026-10-27 用户明确选择“优先逐层等权平均，Q3 C22 接受 9.73”。因此，月度整体满意度均值 9.74 作为参考单列，不再要求它同时等于季度客群均值。

## 周期定义

默认 `january_february_mode = "auto"`：

- 只有 `1-2月` 目录时，1 月和 2 月作为一个周期；
- 只有 `1月`、`2月` 目录时，分别作为两个周期；
- 三个目录同时存在时停止并要求明确配置；
- 可配置为 `grouped` 或 `split`，以固定年度口径。

因此，当前口径下 `1-12月`包含 11 个周期；拆分 1 月和 2 月后自动包含 12 个周期。

## 输出口径

累计汇总表包含 `汇总表`、`周期计算`、`权重核对` 三个工作表。表底整体满意度及各列整体值均取本列有效客群数值的等权均值，沿用单月的十进制四舍五入保留两位小数。

累计分表的下级指标沿用既有跨期权重（独立周期等权，再分给当期有效客群），排除缺失评分后归一化。满意度聚合用精确分数运算避免二进制乘积把 `9.675` 变成 `9.674999999999999`，最终用十进制四舍五入保留两位。一级指标从本分表有效下级指标求等权均值并保留两位；客群总分从有效一级指标求等权均值并保留两位。重要性列沿用原算法。缺失项不当作零分；会展客户的餐饮服务属于配套服务子项，不能另作一级指标重复计入。

再用单月总表相同的 `load_report_snapshots`、`build_summary_rows` 提取总表各客群的总分和指标，用 `build_total_values` 求表底均值，保证两表对应一致。单月流水线及单月结果均不变。

`周期计算` 单列“客群等权汇总”和“各期均值（参考）”。`权重核对` 保留原累计口径的周期贡献及舍入差额，仅作参考。客群缺失、指标缺失会改变分母，两种平均顺序不保证相等，不通过调整指标或填补无评分项来强行配平。

累计分项结果写入与单周期相同的目录结构，PPT继续读取该目录。累计满意度保存值已经只有两位，消除其在分表、总表、PPT 中的二次舍入差异。单月共享统计及显示代码均不改动。

累计日志中的 `summary_source = "generated_detail_reports"` 表示总表取自已生成分表；`section_source = "equal_mean_of_published_child_metrics"`、`customer_total_source = "equal_mean_of_published_first_level_sections"`、`summary_rollup = "equal_mean_of_defined_customer_scores"` 说明逐层均值口径。`checks_scope = "period_contributions_before_detail_summary"` 表示原贡献核对不代替新口径验收。
