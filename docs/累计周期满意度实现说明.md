# 累计周期满意度实现说明

累计批次（例如 `1-9月`、`1-12月`、`Q1`）通过现有单周期统计引擎分别计算每个独立周期，再对独立周期最终总分等权平均。单周期批次（例如 `1-2月`、`3月`）仍执行原有 `run_directory_batch` 路径。

## 周期定义

默认 `january_february_mode = "auto"`：

- 只有 `1-2月` 目录时，1 月和 2 月作为一个周期；
- 只有 `1月`、`2月` 目录时，分别作为两个周期；
- 三个目录同时存在时停止并要求明确配置；
- 可配置为 `grouped` 或 `split`，以固定年度口径。

因此，当前口径下 `1-12月`包含 11 个周期；拆分 1 月和 2 月后自动包含 12 个周期。

## 输出口径

累计汇总表包含 `汇总表`、`周期计算`、`权重核对` 三个工作表。表底整体满意度及各列整体值仍使用各期最终两位小数整体值的平均值。

先按原有算法生成累计分表，再用单月总表相同的 `load_report_snapshots`、`build_summary_rows` 提取总表各客群的总分和指标。取数统一沿用单月的两位小数及缺失项规则，不再对总表同名指标单独进行另一套累计计算。分表算法、单月流水线均不变。

`周期计算`、`权重核对` 保留原累计口径的周期贡献及舍入差额，供理解分表生成前的计算过程；它们不再是主表客群指标的取数依据。主表客群行的普通平均不保证等于表底各月等权整体值，两者代表不同统计口径。

累计分项结果写入与单周期相同的目录结构，PPT继续读取该目录。累计日志中的 `summary_source = "generated_detail_reports"` 表示总表取自已生成分表，`checks_scope = "period_contributions_before_detail_summary"` 表示原贡献核对不代替总表与分表一致性校验。
