# 多周期满意度脚本使用说明

## 运行

在项目根目录运行：

```bash
uv run python multi_period_satisfaction.py --year 2026 --batch 1-9月
```

独立入口 `multi_period_satisfaction.py` 调用新增模块 `src/hangbo/multi_period_satisfaction.py`。原有 `main_pipeline.py`、单周期统计及汇总模块未修改。

新入口读取 `data/raw/2026/1-2月`、`3月`至`9月`，共八个独立周期。它不读取累计原始数据目录 `data/raw/2026/1-9月`，也不将其与独立周期重复计分。全部周期均使用当前单周期算法从原始数据重新计算。

结果写入：

```text
data/satisfaction_summary/2026/1-9月/1-9月客户类型满意度多周期汇总表.xlsx
logs/multi_period/2026/1-9月/calculation.json
```

原始数据、已有单周期结果及原有累计汇总表不会被覆盖。再次运行会更新同名多周期文件。X期列的预处理在临时副本上进行，不补写原始文件的年月，也不生成单周期分项文件、样本表或PPT。

## 周期选择

默认月份范围采用“1–2月为一个完整周期，其余月份独立”的规则。支持 `1-9月`、`3-9月`、`1-12月`、`Q1`至`Q4`。`1-12月`对应11个计算周期。不能将默认合并周期从中间截断，例如 `2-9月`。

自定义批次名称或非连续周期，显式指定：

```bash
uv run python multi_period_satisfaction.py --year 2026 --batch 自选周期 --periods 1-2月 3月 9月
```

以后1月、2月改为独立调查时，可明确列出12个周期：

```bash
uv run python multi_period_satisfaction.py --year 2027 --batch 全年 --periods 1月 2月 3月 4月 5月 6月 7月 8月 9月 10月 11月 12月
```

`--periods`优先于`--batch`的自动周期识别。周期只允许单月或`1-2月`，拒绝重复周期、重叠月份及`1-9月`这样的累计目录。所选独立周期目录缺失或整期无有效分数时停止汇总，不静默减少分母。

其他参数：`--data-root`默认`data`，`--logs-root`默认`logs/multi_period`，`--config`默认`pipeline.defaults.toml`。仅读取该配置中的`sheet_name`和`calculation_mode`，保持每期与单周期脚本相同的指标规则。

## 计算关系

总分严格按各期最终两位小数总分等权平均计算，跨期计算保留完整浮点精度，只在汇总表显示为两位小数。9.71不是固定值，新数据或新增周期会改变结果。

设周期数为T，当期有分数的客户类型数为n。当期客户类型的累计权重为`1/T/n`。无样本或无有效回答的客户类型没有计分权重，不能填成0分。来源文件缺失会明确提示，相应客户类型按无数据处理。

```text
某客户类型累计权重 = 各有值周期的类型权重之和
某客户类型累计总分 = SUM(单期类型总分 × 当期累计类型权重) / 累计权重
最终总分 = SUM(类型累计总分 × 类型累计权重) + 周期舍入贡献
```

一级指标沿相同层级分配权重：周期、客户类型、酒店餐饮有效组件、组件内有效一级指标。先保留每期和每个组件实际使用的权重，再合并同一客户类型的同一一级指标。一级指标累计分数为贡献之和除以权重之和。

酒店餐饮组件独立计分后等权聚合，不能把不同组件的所有指标铺平后再平均。由单期一级指标重建单期类型总分产生的差额记录为“类型舍入差额”，包含组件及类型层面的舍入；不把差额人为加到任何一个客户评分上。

会展、会议类型的“餐饮服务”是配套服务子项，展示分数但计分权重为0；餐饮客户、部分酒店客户的餐饮服务是独立一级指标，正常计分。若把汇总表所有展示列直接求普通平均，会重复计算子项。

```text
类型总分 = SUM(该行一级指标累计分数 × 该单元格累计计分权重) / 类型累计权重
           + 该类型舍入差额

最终总分 = SUM(列底一级指标分数 × 列底一级指标权重)
           + 类型舍入贡献之和 + 周期舍入贡献之和
```

主表中的客户类型分数、一级指标分数、列底分数是上述贡献权重对应的加权结果，未承诺它们都是对应单元格的跨期普通均值。“周期计算”底部另外列出各期列总分均值，避免混淆两种含义。

## 工作表

- `汇总表`：原有客户类型和指标列，另列类型权重、类型舍入差额、餐饮口径。下方列出各单元格的累计计分权重，以及各类型横向核对差额。总分核对差额和各类型横向差额应接近0（浮点误差允许1e-10）。
- `周期计算`：各期总分和各列分数、有效类型数、类型总分均值、周期舍入差额、周期权重和贡献。已存在的历史周期总分只作比较，不参与本次计分。
- `权重计算`：逐周期、逐类型、逐组件、逐一级指标的得分、权重和贡献。餐饮子项另记录展示权重，但计分权重为0；右侧记录类型总分和舍入贡献。

汇总与贡献使用Excel公式，并写入已验证的公式缓存，`data_only=True`读取者可立即获取结果。Excel打开后可重新计算。工作簿展示的是本次运行时的原始数据统计快照，原始数据更新后应重新运行脚本，工作簿不会自动链接外部原始文件。

```text
3月    9.57
4月    9.61

6月    9.74

8月    9.76

均值 = 9.71
```

1–2月历史表保存总分为9.72，当前原始数据与当前算法重算为9.73。历史八期总分均值为9.70875；本次统一重算的八期均值为9.71。两者显示均为9.71，但精确来源不同，不能声称本次重现了历史所有单期分数。此差异已在周期工作表、运行提示和JSON日志中记录。
