# 一级指标均值算法对 2026 年7月、8月、9月总表的影响

核查日期：2026-10-27。

## 结论

以现有单月分表的一级分值为起点，严格执行“客群总分 = 有效一级指标分值的平均，四舍五入到两位”，再生成总表：

| 月份 | 有效分表数 | 比较的总表单元格数 | 有变化的单元格 | 表底整体总分：现有 → 模拟 |
| --- | ---: | ---: | --- | --- |
| 7月 | 15 | 114 | 无 | 9.76 → 9.76 |
| 8月 | 15 | 114 | 酒店餐饮客户总分 C21：9.97 → 9.98 | 9.76 → 9.76 |
| 9月 | 14 | 114 | 无 | 9.70 → 9.70 |

三个单月共比较 342 个位置，包括18类客群的6个分值列和表底6个整体分值列。无数据或不适用的空值、`--` 先统一为空值再比较。只有8月酒店餐饮客户的总分有 0.01 的变化，其他位置均一致。

因此，不能概括为“新规则对所有单月完全没有影响”。准确结论是：本次7月、9月完全不变；8月仅有一个合并客群的总分有 0.01 的差异；三个月的表底整体总分均不变。

## 唯一差异：8月酒店餐饮客户

现有文件：

- `data/satisfaction_detail/2026/8月/酒店餐饮客户.xlsx`：总分 `B2 = 9.97`；一级餐饮服务 `B3 = 9.95`；一级硬件设施 `B16 = 10`；智慧场馆无有效值。
- `data/satisfaction_summary/2026/8月/8月客户类型满意度汇总表.xlsx`：`汇总表!C21 = 9.97`，相应一级指标值与分表一致。

如果严格从这两个有效一级指标重新算总分：

```text
(9.95 + 10) / 2 = 9.975
四舍五入保留两位 = 9.98
```

原有 9.97 来自酒店餐饮子客群的聚合，而不是合并后的一级指标再求平均。本次用原始 `data/raw/2026/8月/餐饮.xlsx` 的临时副本重算，得到：

| 内部子客群 | 样本数 | 餐饮服务 | 硬件设施 | 现有子客群总分 |
| --- | ---: | ---: | ---: | ---: |
| 酒店宴会 | 3 | 10.00 | 10.00 | 10.00 |
| 酒店自助餐 | 24 | 9.89 | 9.99 | 9.94 |
| 酒店餐饮-商务简餐 | 0 | 空 | 空 | 空 |
| 酒店餐饮-宴会 | 0 | 空 | 空 | 空 |

现有代码 `src/hangbo/survey/stats.py` 的 `merge_survey_statistics` 分别平均各子客群总分、各一级指标，并各自四舍五入：

```text
现有合并总分 = (10.00 + 9.94) / 2 = 9.97

合并后的餐饮服务 = (10.00 + 9.89) / 2 = 9.945 → 9.95
合并后的硬件设施 = (10.00 + 9.99) / 2 = 9.995 → 10.00

如果再由合并后的一级指标算总分：
(9.95 + 10.00) / 2 = 9.975 → 9.98
```

所以这 0.01 的原因是合并、平均、四舍五入的计算顺序。现有8月总表与分表彼此对应，均为9.97；但这个聚合客群的总分不严格等于已保留两位的一级指标再平均的结果。若坚持总分严格满足新的一级指标平均关系，两张表中的这一总分应同时改为9.98。
